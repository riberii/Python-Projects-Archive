I developed this project to explore the interaction between user interface elements and mathematical logic in a desktop application environment. The goal was to create a calculator that doesn't just display a result on the same screen, but actually triggers a new window to show the output. This required a deep dive into Tkinter's Toplevel widget and how to pass variables between different parts of a running application. By using radio buttons for operator selection, I focused on creating a clean, intuitive user experience that prevents input errors before they happen.

The technical foundation of the calculator is built on a structured grid system within an ivory colored frame. I used tk.IntVar() to track the state of the numbers and the selected operator in real time. This project helped me master the two primary ways of organizing widgets in Tkinter: grid() for structured rows and columns, and place() for exact pixel positioning. I had to ensure that the "Equal" button correctly identified which radio button was selected (1 for addition, 2 for subtraction, etc.) before performing the calculation, which is a key concept in managing application state.

The most interesting part of the development was the implementation of the New_Window() function. Instead of a simple print statement, this function creates a separate window, performs the calculation based on the current tk.IntVar() values, and renders a new label with the result. I implemented defensive logic to handle different operations within this window, including basic division and multiplication. This taught me how to manage "parent" and "child" windows in a software application, ensuring that the main program keeps running while the user interacts with the result popup.

In the future, I plan to add more advanced error handling, such as a popup warning if a user tries to divide by zero or leaves an entry field empty. I also want to improve the visual design by using the ttk (Themed Tkinter) module to add more modern looking buttons and input fields. Another goal is to add a "History" feature that logs previous calculations in a text box on the main screen, allowing users to keep track of their work without opening multiple windows. This project has been a vital step in learning how to build tools that are both functional and visually organized.
